# C++ TensorRT 部署端性能测试报告

## 1. 测试环境
- **硬件**: RTX 3050 Laptop (4GB)
- **软件**: WSL2 Ubuntu + CUDA 12.6 + TensorRT 10.7 + OpenCV 4.10
- **编译**: GCC 15.2, `-O2` 优化
- **模型**: YOLOv8n (输入 416x416, batch=1)
- **测试方法**: Warmup 10 次，基准测试 100 次

## 2. 最新测试结果 (FP16 纯 C++ 端到端)
| 指标 | 耗时 (ms) | 吞吐量 (FPS) |
| :--- | :--- | :--- |
| **平均延迟** | **3.73 ms** | **267.65** |
| 最小延迟 | 2.98 ms | - |
| 最大延迟 | 6.39 ms | - |

> *注：测试包含图像读取、CPU 预处理（HWC转CHW、归一化）、GPU 推理、后处理（DFL解码与NMS）的全链路耗时。*

## 3. 全阶段性能对比 (基准)
| 阶段 | 耗时 (ms) | FPS | 说明 |
| :--- | :--- | :--- | :--- |
| PyTorch (Python) | 14.6 ms | 68 | 原始模型纯推理 |
| TensorRT FP16 (Python) | 3.72 ms | 269 | 纯推理 (不含前后处理) |
| TensorRT INT8 (Python) | 3.53 ms | 221 | 纯推理 (INT8 在小图上调度开销大) |
| **TensorRT FP16 (C++ 端到端)** | **3.73 ms** | **267** | **当前工程：纯 C++ 全链路** |

## 4. 结论与后续优化方向
- **性能达标**：目前 C++ 端到端延迟 **3.73ms**，极限帧率 **267 FPS**，相比纯 PyTorch 提升了近 4 倍，完全可以满足工业产线实时检测需求。
- **当前瓶颈**：目前耗时主要卡在 CPU 端的 OpenCV 预处理（`cv::resize` 与 `for` 循环通道转换）以及 CPU-GPU 之间的数据拷贝。
- **下一步优化 (CUDA 化)**：
  - 引入自定义 CUDA Kernel，将图像预处理（Resize + HWC转CHW + 归一化）从 CPU 迁移至 GPU 并行计算。
  - 目标：消除 CPU 瓶颈，实现零内存拷贝，预计端到端耗时将突破至 **2.5 ms** 以内。
